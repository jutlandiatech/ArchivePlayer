# Getting started

How to clone, build, test and run ArchivePlayer on your own machine.

## 1. Install

| Tool | Version | Notes |
|---|---|---|
| [Android Studio](https://developer.android.com/studio) | current stable | Bundles a JDK 17+ (JetBrains Runtime) and the SDK Manager. |
| Android SDK Platform | 37 | SDK Manager → SDK Platforms. |
| Android SDK Build-Tools | 37.0.0 | SDK Manager → SDK Tools. |
| Android Emulator + a system image | API 36 or 37, x86_64 (or arm64 on Apple silicon) | Only needed for UI tests without a phone. |
| Git | any recent | |
| Python 3 | 3.10+ | Only to regenerate text catalogs / category map (`tools/gen_*.py`). |

Gradle itself is not installed separately: the wrapper (`gradlew`, `gradlew.bat`) downloads Gradle 9.9.0 on first use.

Command-line only (no Android Studio): install a JDK 17+, the Android command-line tools, then
`sdkmanager "platform-tools" "platforms;android-37.0" "build-tools;37.0.0"` and set `ANDROID_HOME`.

## 2. Clone and open

```bash
git clone https://github.com/jutlandiatech/ArchivePlayer.git
cd ArchivePlayer
```

In Android Studio choose **File → Open** and select the `ArchivePlayer` folder. Let the Gradle sync finish. Android Studio writes `local.properties` with your SDK path (it is git-ignored).

## 3. Build variants

The app has two flavours (dimension `distribution`):

| Variant | Contents |
|---|---|
| `fullDebug` / `fullRelease` | Everything, including Chromecast (Google Play Services, Media3 Cast, MediaRouter). |
| `fossDebug` / `fossRelease` | No Google Play Services, Cast, MediaRouter or Firebase. Checked by `:app:verifyFossDependencies`. |

Pick the variant in **Build → Select Build Variant**, then run on a phone or emulator.

## 4. Commands

macOS/Linux use `./gradlew`; Windows uses `gradlew.bat` or `.\tools\run-gradle.ps1`.

```bash
./gradlew :core:test                                   # pure Kotlin domain tests (fast, no device)
./gradlew :app:assembleFullDebug :app:assembleFossDebug # APKs in app/build/outputs/apk/
./gradlew :app:verifyFossDependencies                  # FOSS flavour stays Google-free
./gradlew --continue :app:connectedFullDebugAndroidTest :app:connectedFossDebugAndroidTest  # UI tests, needs a device
```

Single UI test:

```bash
./gradlew :app:connectedFullDebugAndroidTest \
  -Pandroid.testInstrumentationRunnerArguments.class=<package>.PlayerUiTest#P01_miniPlayerAcrossTabs
```

UI tests never touch archive.org: a local fake server (`app/src/androidTest/.../support/FixtureServer.kt`) serves recorded responses and small generated media. Each test starts from a fresh install (test orchestrator with `clearPackageData`).

## 5. Where things live

See the code map in the [README](../README.md#code-map). Texts shown in the app come from `app/src/main/assets/texts/TextCatalog_*.json`, generated by `tools/gen_text_catalogs.py`; edit the script and re-run it rather than editing the JSON. The same applies to `tools/gen_category_map.py` and `app/src/main/assets/catalog/category-map.json`.

The GitHub Pages site (share page, category map) lives in `site/`; open `site/p/index.html#<fragment>` in a browser to try a share link locally. Publishing and App Link setup are in [APP_LINKS.md](APP_LINKS.md).

## 6. Working on a change

1. Find or add the requirement in [SPECIFICATION.md](../SPECIFICATION.md) or the matching `UI_*_SPEC.md`.
2. Write the failing test first, named after the requirement/scenario ID (see [TESTING.md](../TESTING.md)).
3. Implement until it passes; run `:core:test`, both flavours' UI tests and `:app:verifyFossDependencies`.
4. Open a pull request against `main`.

## 7. Optional: AI coding agents

Nothing in the build depends on an AI tool. If you use one (for example Devin, GitHub Copilot, Claude Code, Cursor or Android Studio's Gemini), these files give it the context it needs:

- `SPECIFICATION.md` and the `UI_*_SPEC.md` files: requirements, scenarios and the element-ID contract the UI tests rely on.
- `TESTING.md`: how tests are named and run.
- `DEVELOPMENT_ENVIRONMENT.md`: toolchain versions and known gotchas (e.g. emulator image issues).
- `ArchivePlayer.code-workspace`: VS Code tasks for the common Gradle commands.

Keep the specification-first workflow: let the agent update the spec and tests before the implementation, and review its changes like any other pull request.

## 8. Things only a real device can check

Automated tests cover the logic and the UI on an emulator. Before a release, check on real hardware:

- Casting to a physical Chromecast (`full` flavour): connect, play, pause, seek, queue, disconnect and resume locally. Check both a video and an audio entry, including one you have downloaded (the Chromecast must stream it from archive.org), and that the phone stays in portrait while casting (R46, R86).
- Full-screen video: maximize a widescreen film (phone turns to landscape, bars hide, controls fade after about 3 s), tilt back to portrait or press Back to leave; a portrait video stays portrait (R86).
- Downloads to a removable SD card: choose the SD card in Settings, download, remove the card, re-insert it.
- Picture-in-picture for video: home button during playback, controls in the PiP window, return to the app.
- Phone and tablet layouts (bottom bar below 600 dp width, navigation rail above), portrait and landscape.
- Smooth scrolling of long lists and playback start time on a low-end phone.
